# Changelog

## 1.0.1 — 2026-10-16
- **A CodeBuddy usage limit now switches accounts.** CodeBuddy reports a limit (`429 usage exceeds frequency limit … reset at 2026-10-17 11:28:41 UTC+8`) as a failed result row with no `result`, the reason only in `errors` and `errors_info` (`status: 429`, `category: quota`), and exits 0. Hydra read only `result`, so the failure text was empty: the Head resumed into the same 429 every round, ended with 0 tokens and no report, and never moved to the next account. `buddyFailureText` now reads `errors` and `errors_info` too, a round that stopped on a usage limit is not resumed, and the account cools until the reset time. WorkBuddy runs the same code.
- **Cooldowns read a date and time with a space and a `UTC+8` / `GMT-05:00` offset**, as CodeBuddy prints its reset; a date and time without a zone is local time. `isQuotaFailure` also reads `frequency limit`.

## 1.0.0 — 2026-10-15
- **WorkBuddy engine.** `/hydra engine=workbuddy` runs Heads through the CodeBuddy CLI pointed at the WorkBuddy app's product config (`ACC_PRODUCT_CONFIG_PATH=~/.workbuddy-ai/cache/acc-product-config-v3.json`, undocumented by Tencent) in its own config folder (`~/.claude/hydra/workbuddy-cli`), with CodeBuddy's memory, session summaries, prompt suggestions, cron, IDE and browser MCP switched off. Same code, rules and write guard as CodeBuddy; default model `deepseek-v4.1-flash`; tokens, not dollars (credits). `/hydra` says to install the WorkBuddy app when the product file is missing and how to sign in when the folder has no login. Extra accounts get their own `CODEBUDDY_CONFIG_DIR`. Verified live: one round (`--max-turns 3`) answered `HEAD DONE` with exit 0.
- **OpenCode engine (beta).** `/hydra engine=opencode` runs Heads through `opencode run --standalone --format json` (built against OpenCode v2.0.18). The default model is `opencode/deepseek-v4.1-flash-free`, which needs no account, and the Lead may pass any `provider/model` set up in OpenCode. **The lockdown is weaker than the other engines'**: OpenCode's own permission rules only, no OS sandbox and no write guard, and the consent question says so. Each Head gets its own config file (deny by default, nothing at `ask`, reads without `.env` or credential folders, edits inside the project without `.git` or `.env`, `external_directory` closed except `writeDirs`/`addDirs`, outward symlinks denied by path) and an empty config home, so `~/.config/opencode` and project configs never apply. OpenCode Heads never get a shell (`shell: true` is ignored: OpenCode does not check a command's paths), grep (it leaks `.env` lines), web, subagents or the `execute` code tool. Reports flag any tool that ran although denied.
- **Verified live (OpenCode v2.0.18, free model):** edit `a.txt` and create `b.txt` succeed; `.env`, `sub/.env.local`, `../sibling/x.txt`, a file in home, `~/.ssh/config`, `.git/config`, OpenCode's temp folder, the Head's config folder and a glob in `~/.ssh` are refused; shell, grep, `execute` and webfetch are not offered to the model. A write through a project symlink to a sibling folder **succeeded** under the first config; the symlink rule now refuses it (and a read through it). A `-s` resume recalled the session.
- **OpenCode lockdown hardened.** On a case-insensitive disk `.GIT/hooks/pre-commit`, `.Git/config` and `.ENV` got past the rules: `.git` and `.env` are now denied in all 8 letter cases, and links and other path denies match any case (`anyCase`). OpenCode matches every path under the repository root relative to `cwd`, without its `external_directory` check, so an OpenCode Head is now refused unless `cwd` is the repository root (or there is none). A grant that holds a credential folder (`addDirs` of the home folder) is refused. Symlinks are found by `bin/symlinks.py` in the project and every `addDirs`/`writeDirs` folder, with nothing skipped and inward links filtered before any count; a scan that fails, times out or is cut short, or more than 100 links to deny, refuses the Head. Links to a folder above themselves (`a -> .`), or to `.git`, `.env`, protected or read-only places, are denied too. Edits to `.opencode/`, `opencode.json*`, `.claude/` and `.codebuddy/` are denied. A pattern that reads as a number keeps its place after `*`. The report warns (⚠) about a changed file whose real path is in a `.git` folder or outside the project.
- **OpenCode runs where it is told.** `opencode run` changes to `$PWD` before anything else, and `$PWD` was Claude Code's own folder, so a Head with another `cwd` worked (and was matched) there; Heads and checks now set `PWD`. Heads also set `OPENCODE_CONFIG_PROJECT_DISABLE=1` next to `OPENCODE_DISABLE_PROJECT_CONFIG=1`, and the preflight runs from the home folder with both set. It reads `auth list --format json` (plain output said "No authenticated integrations", which counted as signed in), and an extra account counts as signed in only with a stored credential (`opencode.db` exists after any OpenCode command). A silent round retried after the watchdog resumes the session it started instead of opening a second one.
- **Verified live (OpenCode v2.0.18, free model, 15/10/26), the code's own config and env:** refused: a `.GIT/hooks/…` write, a `.Git/config` and a `.git/config` edit, `.ENV`, `.env` and `sub/.Env.local` reads, `../sibling/x.txt`, `~/.ssh/…`, writes through `link-out/` and `LINK-OUT/` (outward link), `self/link-out/` (`self -> .`), `.claude/settings.json`, a read through an outward link in an `addDirs` folder and a write through `LINK-OUT3/` in a `writeDirs` folder. Allowed: a project write and an `addDirs` read. Refused before running: a monorepo subfolder `cwd` and an `addDirs` of the home folder.
- **A watchdog for silent CLIs.** `pump` takes an optional `idle` limit and stops a child that prints nothing for too long (signal `idle`). OpenCode Heads use 90 s before the first event and 5 min between events, retry a silent round once, then report the hang.
- **Usage limits:** `isQuotaFailure` also reads `provider.rate-limit`, `provider.quota`, `insufficient credits` and `PREMIUM_CREDITS_EXHAUSTED`. OpenCode `error` events reach the account switch as `type: message`.
- New `hooks/opencode.test.ts` and `hooks/workbuddy.test.ts`; `ENGINES` is now `commandcode, codebuddy, codex, agy, workbuddy, opencode`. Neither new engine runs on native Windows yet.
- **Several accounts per engine, switched automatically.** `/hydra accounts add <engine> [name]` makes an account folder under `~/.claude/hydra/accounts/<engine>/<name>/` and prints the login command to run (`CODEX_HOME="…" codex login`, `CODEBUDDY_CONFIG_DIR="…" codebuddy` then `/login`, `HOME="…" agy`; PowerShell forms on Windows). Hydra never handles credentials. Codex, CodeBuddy and Antigravity support it; Command Code keeps one account. `/hydra accounts` lists them with their sign-in state and any cooldown, `remove` forgets one (its folder stays), `reset` clears cooldowns. The default account stays the CLI's normal sign-in.
- **Usage limits move a Head on.** When a Head stops with a usage or rate limit in the CLI's own error output, Hydra marks that account cooling (for the wait the CLI names, else an hour, at most 7 days) and re-runs the Head on the next free account with the original task plus a note listing the files already changed, one run per account at most. The report starts with `accounts: codex/default (usage limit, cooling until 14:05) → codex/work`. With every account cooling the Head does not start and the report says when the earliest frees up; the auto-mode policy tells Claude to route that task to another engine. Only the CLI's failure text is tested, never the model's report.
- **`accountStrategy`** option: `fill` (default, the default account first) or `spread` (least recently used first). `/hydra-usage` shows an Accounts section once an extra account exists, `/heads` shows the account a Head ran on.
- New `hooks/accounts.test.ts` (quota wording, cooldown parsing, picking, login commands, argument parsing, the store, and the rotation with fake steps). `parseHydraArgs` has the `accounts` action; its other results are unchanged.
- **Smaller first run.** `headEngine` now defaults to `auto`. A bare `/hydra` checks every engine: a configured single engine that is ready is used as before; otherwise one ready engine is used alone (`Using Codex (the only engine ready here).`), two or more become an auto pool, and none shows a compact setup card (one line per engine from the install hints, the recommended ones first, ending with `then run /hydra again`). Consent is asked exactly as before, before anything is sent to an engine. The first time Hydra turns on on a machine, the reply adds three lines on what happens next (kept under the store key `welcomed-v1`). `/hydra help` is updated.
- **Totals and a timeline in `/heads`.** The pane opens with a summary (running, queued, done and failed counts, tokens and dollars where known, edits, denials, session wall time), a per-engine line when more than one engine ran Heads (`codex 3 · agy 2`), and a timeline with one bar per Head across the session's span, coloured by state, with its elapsed time at the right. The band above the prompt shows the live Heads' total tokens and dollars in its header and keeps one line per Head at any width (it drops the effort, the bar and the turn count at narrow widths, never a row). `/hydra-usage` has a "This session" section with Heads, tokens and dollars per engine. Layout and sums are pure helpers in `lib/format.ts`; `hooks/ui.test.ts` tests them, the onboarding decision and the three views on both surfaces.
- **Breaking: Codex Heads no longer read the home folder.** The profile now closes the home folder and opens only the project, `addDirs`, `writeDirs` and the toolchain folders a build needs (git config, nvm, volta, bun, pnpm, cargo, rustup, pyenv, rbenv, asdf, mise, gradle, maven, sdkman, Go, Flutter, Dart, .NET, the Android SDK, conda…), each only if it exists. Other repos, documents and dotfiles are unreadable; name a folder a Head must read in `addDirs`, or add home folders for every Head with the new **`headReadDirs`** option. A Head started in a monorepo subfolder or a git worktree also reads the repository's top level and shared `.git` folder. A project that is `/`, the home folder or a folder above it is refused on every engine.
- **One credential list for every engine** (`SECRET_PATHS`, lib/safety.ts): SSH and GPG keys, git credential stores, cloud logins (AWS, Azure, gcloud, kube, Docker, Terraform, Vault, doctl, 1Password), registry tokens (`.npmrc`, `.yarnrc`, `.pypirc`, cargo, gradle.properties, maven settings, pub), keychains and password stores, and the agent CLIs' own sign-ins. Codex denies them in its profile, Command Code, CodeBuddy and WorkBuddy by read and shell rules, Antigravity by read rules, OpenCode by its permission config. An `addDirs` or `writeDirs` folder inside one is refused, a `writeDirs` folder that holds the home folder is refused, and `headReadDirs` entries that are, sit in or hold a credential path are dropped. Command Code's shell rules now name the folder under home only, so a project's own `.docker` stays usable. Verified live through Codex's sandbox: the project and `addDirs` read, toolchains run, and `~/.ssh`, `~/.claude`, `~/Documents`, a grant inside `~/.aws` and writes outside the project are refused.
- **Codex profile fixes.** A path named twice made Codex reject the whole profile; each path now appears once with the stricter access. A transient `error` row (Codex retrying a connection) no longer fails a turn; only `turn.failed`, or an error with no completed turn, does. An empty `HOME` refuses the Head instead of running without a closed home.
- **Codex falls back to `gpt-6-luna`.** Some ChatGPT plans refuse `gpt-6.1-sol` ("not supported when using Codex with a ChatGPT account"), which failed every Codex Head at once. The Head now reruns on `gpt-6-luna`, its report carries a ⚠ line, and later Heads in the session start there.
- **A signed-out CodeBuddy or WorkBuddy stops the Head.** CodeBuddy answers "Authentication required" as a normal reply, so a Head used to resume eight times and report nothing; that reply now ends it with a sign-in message.
- **Background reports in one line.** A background Head's report shows in the transcript as `🐉 Head <name> · ✓ finished · 3 files edited · report sent to Claude (/heads for detail)`; the full report reaches Claude beside it, framed as untrusted data (the Head's own text cannot pass Claude instructions or fake the summary line).
- **Accounts:** parallel Heads in `spread` mode claim an account as they pick it, so a fan-out spreads; a Head that switched accounts reports the tokens of every run; cooldowns read "try again at 3:05 PM" and millisecond waits; sign-ins are run in a separate terminal (they are interactive). Only a short Antigravity response counts as the CLI's failure reason, so a report that mentions rate limits cannot switch accounts.
- **Windows.** Hydra finds CLIs through `where.exe` (an npm `.cmd` shim runs as `node <script>`, avoiding `cmd.exe`'s line limit and quoting), runs its Python helpers with `py -3` or `python`, reads `USERPROFILE`, and quotes the write guard for the Windows command line. Heads still refuse to start on native Windows, because no engine's lockdown there can deny reads; run Claude Code under WSL, where everything works as on Linux.
- **Every engine honours a stop that came before the Head started**, and every CLI is started with stdin closed.
- **Open source housekeeping.** MIT licence, SECURITY.md, CONTRIBUTING.md, issue and PR templates, `.editorconfig` and `.gitattributes`. CI runs `ruff` and `pytest` on Linux, macOS and Windows (Python 3.9 and 3.13) and `claude plugin validate` plus `claude plugin test` on Linux and macOS (Claude Code pinned). `hooks/register.tsx` is split into `hooks/lib/*` and `hooks/engines/*`; the Lead's auto-mode policy is a quarter shorter.

## 0.12.0 — 2026-10-13
- **Auto engines.** `/hydra engine=auto` (or `engines=codex,agy,codebuddy` for a chosen pool, which implies auto) lets Claude pick the engine for each Head from the task, instead of the whole session running on one. Hydra checks which engines are installed and signed in, drops the others with a note saying what to run, and asks consent once for every engine in the pool. `/hydra effort=…` and other changes keep an auto session auto.
- **Claude routes by the task.** In auto mode the Head tool takes an `engine` field and refuses a call without one, so the choice is deliberate. The Lead's policy lists only the pool's engines with what each is for (Codex: hard, multi-file, test-running work, `model: "gpt-6-luna"` for easy; Antigravity: fast, big-context reading, boilerplate and bulk simple edits on `gemini-3.8-flash`; CodeBuddy: the measured cheap default for well-specified edits; Command Code: the same DeepSeek model with dollar tracking), and routing rules: cheapest engine that can do it, the hard fifth on the strongest, tasks on disjoint files in parallel on different engines, a failed Head goes up one effort level on the same engine and then to a stronger one. These are judgement from how the engines run, except CodeBuddy's 95% over 126 runs, which is the old DeepSeek measurement; no cross-engine benchmark exists yet.
- **`/hydra engines`** lists the four engines with a ✓ or ✗ (and what to run when ✗) and what each is for.
- **Per-Head models.** Each Head gets its engine's own default model (`gpt-6.1-sol`, `gemini-3.8-flash`, or the configured DeepSeek one); a `model` the Lead passes that the engine cannot run is ignored. In a fixed-engine session the `engine` field must be omitted or match. The band above the prompt, `/heads`, the status line (`🐉 Auto codex+agy · low`), reports and `/hydra-usage` show the engine and tokens.
- `mcp__hydra__control` takes `engine: "auto"` and `engines: […]` too. Switching the engine or the pool through it checks that each engine is ready and that the person agreed to it, as `/hydra` does; the Head tool also refuses an engine without that consent. The type-check (`tsc --noEmit -p .`) is clean for the whole mod.

## 0.11.0 — 2026-10-13
- **Antigravity engine.** Heads can run on Google's Antigravity CLI (`agy -p --output-format stream-json`): `/hydra engine=agy` (or `headEngine`, or the Lead's `mcp__hydra__control`). Antigravity Heads **always run `gemini-3.8-flash`** (the person's choice): a `model` the Lead passes is ignored, and effort maps to its three levels (`off`/`low` → low, `medium`, `high`/`xhigh`/`max` → high). Reports, the band and `/heads` show tokens (Google account quota, no dollars).
- **Lockdown by permission rules plus the terminal sandbox.** `agy` has no per-run settings flag and reads one global `~/.gemini/antigravity-cli/settings.json`, so each Head runs with its own `HOME` (`~/.claude/hydra/heads/agy-<session>-<head>/`, owner-only, holding that Head's `settings.json` and a copy of the sign-in token; removed when the Head ends, stale ones swept after a day). The rules: `write_file(<dir>/)` only for `cwd` and `writeDirs`, `read_file(<dir>/)` for `addDirs`, `write_file(<dir>/.git/)` denied, `read_file(<file>)` denied for each `.env` / `.env.*` that exists under those folders when the Head starts, credential folders (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.codex`, `~/.claude`, `~/.config/gcloud`, `~/.netrc`, `~/.npmrc`, `~/.git-credentials`, `~/.gemini`) denied for reads. A shell (`command(*)`) is allowed only for `shell: true`, always with `--sandbox` (without it an allowed shell is wide open: sibling folders, `.env` and the network all worked), and Command Code's dangerous-command list is added as deny regexes.
- **Verified live** against `agy` 1.3.4 and `gemini-3.8-flash`: in-project edit and create, a `writeDirs` write and an `addDirs` read succeed; a folder beside the project, a write to an `addDirs` folder, `.env` and `sub/.env.local` (existing), `.git` writes, `git commit`, `rm -rf`, `curl` and writes outside the workspace by file tool are refused, and a harmless `echo through here` still runs. Writes to `/tmp` are refused (outside the project).
- **A refused call ends the Head's turn** (`denied_actions` in the result, with no path), so Hydra's resume loop continues the conversation (`--conversation <id>`) and lists what stays denied; the report names the last call before the stop. Edited files come from `bin/changed-files.py`, because the stream does not say whether a file tool call was refused.
- **Gotchas found:** `--add-dir` turns the project read-only inside `--sandbox` (Hydra does not pass it); `\b` does not work in rule regexes, so the dangerous-command rules match the command at the start of the line or after `;`, `&`, `|`, `(`; `.env` files created after the Head starts are not covered.
- Turns are tool calls and the default cap is 150, as on Codex.
- **Temp folders closed.** `/tmp`, `/var/tmp` (and the macOS `/private/…` ones) are denied for writes unless one of the Head's own folders lives there, because the sandbox otherwise leaves them writable (verified: a Head under the home folder can no longer write `/tmp/x`).
- **`.env` files are looked for again before every round**, so a resumed Head is also kept from one that appeared since the last round. Rules cannot name a pattern (globs and regexes in `read_file` make the sandbox refuse every command), so a `.env` created while a round runs stays readable until the next round.

## 0.8.0 — 2026-10-09
- `effort=auto` now follows a rule measured on real Heads instead of a guess. A new benchmark (`bench/effort/`: 15 tasks from a rename to a spreadsheet engine, hidden tests, reference solutions) ran 126 Heads on DeepSeek V4.1 Flash at `low`, `high` and `max`, three times each. `low` passed 95.2% at $0.0087 and 72 s a task; `high` 95.2% at $0.0118 and 94 s; `max` 97.6% at $0.0294 and 260 s. Starting at `low` and retrying one level up after a failed check passed 100% at $0.0103 and 86 s: as reliable as anything, for less than `high` alone.
- The rule the Lead gets: `low` (now also the default when it gives none) for every Head whose result it will check by running something, or by reading the diff for mechanical edits; one level up on each retry, with the failure in the task (`low`, `high`, `max`), then rewrite the brief or do it itself; `max` first only for subtle work it cannot check cheaply; never raise effort to make up for a vague brief. The Lead may pass any level from `low` to `max`.
- Checked the rule itself: five fresh Leads (three Opus, two Sonnet) given only the rule picked the expected level in all 24 situations of `bench/effort/select/` (first Heads with and without a check, retries, a migration, a hotfix).
- With a DeepSeek V4.1 Flash Head the rule notes that `medium` runs as `high` and `xhigh` as `max` (the model takes `off`, `low`, `high`, `max`), so those levels could not be measured separately.

## 0.7.1 — 2026-10-08
- A Head can no longer create files outside the project. New files directly in a folder above the project are denied by rule (`Edit(//<folder>/*)`, PR #15). New folders there (`~/new/x`, a missing `~/.ssh/authorized_keys`), which no deny rule can name because `write_file` creates missing parents, are denied by a write guard: a Command Code `PreToolUse` hook (`bin/head-guard.py`) that checks each write's real path, symlinks resolved, against the project. Verified with a live `--yolo` Head.

## 0.7.0 — 2026-10-08
Ready for people other than its author.
- Install with one line: the repo is its own marketplace (`/plugin install hydra --marketplace Shakibuzzaman3104/claude-hydra`). The README is rewritten for new users; internals, the smoke test and pitfalls move to DEVELOPING.md.
- `/hydra` checks the setup first (macOS/Linux, the Command Code CLI, `python3`, `git`, a Command Code sign-in) and says what to run instead of failing inside a Head.
- The first `/hydra` asks once before any code goes to the Head model, and says how Heads are locked down. The Lead's `control on` can't skip that.
- Fix: the Head rules file (`.commandcode/settings.local.json`) is deleted when the last Head in a project ends. It used to stay, so the person's own Command Code runs there had shell and outside edits denied with no visible reason. Each running Head is listed in the file with its session and an end time, so sessions sharing a project keep each other's lockdown, and a crashed session's entries expire. A session start cleans up after a reload or crash.
- A typo is no longer a task: `/hydra stauts` or `/hydra efort=max` names the unknown option instead of turning Hydra on and sending the word to Claude. New `/hydra help` and `/hydra statusline`.
- `/limits` is now `/hydra-usage`.
- No personal defaults: the Heads' 5-hour and weekly caps default to 0 (spend shown without a limit), the plan name to empty; set them in `/config`. `headEffort` is a picker there.
- `/heads` shows a finished Head's edited files and the last lines of its report, moves with `j`/`k`, and keeps the last 20 Heads.
- Error messages say what to do (the person's own rules file, an unwritable project, a Head that could not run).
- Status files of other sessions are deleted after a week.
- A Head refuses a Windows project path instead of running unlocked: Command Code's rules cannot name a drive, so writes outside the project could not be denied (PR #13). Use WSL.

## 0.6.3 — 2026-10-08
- Heads default to `deepseek/deepseek-v4.1-flash-fast`, the high-throughput deployment of V4.1 Flash (Command Code says full weights). Same effort levels (`off`, `low`, `high`, `max`); a smoke test gave matching answers in 3 s against 5 s. Cache reads cost more ($0.02/M against $0.003/M), and Command Code has not scored it yet. Set `headModel` to `deepseek/deepseek-v4.1-flash` to go back.

## 0.6.2 — 2026-10-08
- `/heads` and `/limits` are immediate commands: they open at once mid-turn instead of interrupting Claude, which used to cancel a foreground Head.
- An interrupted foreground call (Esc, a typed prompt) no longer kills its Head: the Head keeps running and its report arrives as a message. Only a deliberate stop ends it.
- `/heads` has a Stop button (`s`) for the Head in view; `mcp__hydra__control` stop shares the same path.
- Verified live: a turn interrupted 20 s into a foreground Head left it running; it finished all 12 edits and reported as a message.

## 0.6.1 — 2026-10-08
- Fix: a foreground Head failed after 10 s with "the Head run failed before it reported". The `tool.call` hook waited on a plain promise, which counts against a hook's 10 s budget; it now waits through `$` calls (a host `sleep`), which do not. Verified live: a foreground Head ran 19 s and reported; a background Head was stopped by name through `mcp__hydra__control`.

## 0.6.0 — 2026-10-08
- Heads get short meaningful names (`prefs-utils`, `login-tests`) instead of `h` + digits: the Lead passes `name`, else Hydra makes one from the task's first source file or first words; unique per session.
- Every Head, foreground or background, runs on the session's own worker, so cancelling a Head's tool call stops it cleanly instead of leaving it shown as running. The stream read is raced against the stop signal, so a silent Head (a model thinking, a hung CLI) cannot hold a stopped run open.
- New `mcp__hydra__control` tool for the Lead: `list` the Heads (stale ones flagged NO LIVE PROCESS), `stop` one or all, `clear` finished ones, and turn Hydra `on`/`off` or set its `effort`.
- A reload marks queued Heads as ended too, not only running ones.
- `/hydra <task>` submits the task as a prompt, so the Lead starts at once instead of waiting for the next message.
