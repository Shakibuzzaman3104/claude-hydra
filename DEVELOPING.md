# Developing Hydra

## Running a working copy
1. Clone the repo and copy it where Claude Code loads it, leaving out the generated types:
   ```
   git clone https://github.com/Shakibuzzaman3104/claude-hydra ~/claude-hydra
   mkdir -p ~/.claude/mods && rsync -a --exclude .git --exclude .claude-plugin/types ~/claude-hydra/ ~/.claude/mods/hydra/
   ```
2. Load it in every session: add `"CLAUDE_CODE_PLUGIN_DIRS": "~/.claude/mods/hydra"` to the `env` block of `~/.claude/settings.json`. Don't also install it from the marketplace, or `/hydra` registers twice (the same goes for a copy under `~/.claude/dev-mods/*/hydra`).
3. Check it: `claude plugin validate ~/.claude/mods/hydra` and `claude plugin test ~/.claude/mods/hydra` pass.
4. In a new session, `/hydra` answers `🐉 Hydra on · Lead … · Head <model> · effort auto …`, and the `mcp__hydra__head` tool lists `addDirs`, `shell`, `effort`, `maxMinutes` and `background`. A tool without those is an older copy.

## How a Head runs (internals)
- **Why `--yolo`:** Command Code's headless (`-p`) mode has a built-in gate that blocks `edit_file`, `write_file` and `shell_command` unless the run uses `--yolo`; permission rules cannot lift it. So every Head runs with `--yolo`, locked down by deny rules, which yolo still honours.
- **Locked down:** before a Head starts, Hydra writes the project's `.commandcode/settings.local.json` (added to `.git/info/exclude`):
  - every folder outside `cwd` is denied for edits, sibling by sibling up to `/`, and so is any new file directly in a folder above `cwd`;
  - a write guard (`bin/head-guard.py`, a Command Code `PreToolUse` hook in the same file) denies every write or edit whose real path, symlinks resolved, is outside `cwd`. Deny rules cannot name a new folder (`write_file` creates missing parents, so `~/new/x` or a missing `~/.ssh/authorized_keys` slip past them); the guard can. It also denies a symlink inside the project that points out of it. Command Code runs a tool when its hook crashes, so the deny rules stay as the floor;
  - `.git` and `.commandcode` inside the project are denied;
  - `writeDirs` (a Head input) opens folders outside `cwd` for writing, resolved to their real path: the ancestor rules leave a way down to each, the guard takes each as a root, and `.git`, `.commandcode` and `.env` files inside them stay denied. A symlink in the project only works with its target granted, because Command Code checks a path's real location against the deny rules too. `/`, home, a folder above the project and one inside it are refused;
  - shell is denied outright unless a running Head asked for `shell: true`; even then destructive git, `rm -r`/`-f`, `sudo`, network tools (`curl`, `wget`, `ssh`, `rsync`, …), builds and installs (`xcodebuild`, `swift build`, `npm install`, `brew`, …) stay denied;
  - `.env` and `.env.*` files are kept from Heads, because a Head sends file contents to an external model: the read and edit tools are denied on them, and so is any shell command that names one as a path (`Shell(* .env*)`, `Shell(*/.env*)`, `Shell(*=.env*)`; `process.env` still runs);
  - the grep tool ignores `Read` rules and takes no path-scoped deny, so when a `.env` file sits in the project or an `addDirs` folder Hydra denies the grep tool outright (the report says which file); if the check fails, search is denied too;
  - a Head with `shell: true` can still read `.env` through a command that does not name it, such as `grep -r KEY .`. Pattern rules cannot close that, so avoid shell in projects with real secrets.
  Heads sharing a `cwd` share one file, rebuilt from the Heads running there as each starts and ends, from every Claude session: the file's `hydraHeads` lists each running Head (`<session id>/<head id>`) with a time it must have ended by, so one session never drops another's lockdown and a crashed session's entries expire. When the last Head leaves, the file is deleted, so the person's own Command Code runs never inherit Hydra's rules. A session start also clears what a reload or crash left behind in the session root.
- **Fails closed:** if the rules cannot be written, or the project already has a `settings.local.json` the person wrote, the Head does not start and the report says why.
- **Audit:** each report lists the files that Head edited and every denied call, read from its own transcript, and puts any write outside the project at the top as `⚠ WROTE OUTSIDE THE PROJECT`.
- `addDirs` grants read access to folders outside `cwd` (mockups, briefs, other repos).
- **Never quits silently:** a Head that stops before ending its report with `HEAD DONE` (a text-only reply, an empty model reply, a turn cap) is resumed in the same session, up to 8 rounds, and told which calls stay denied. A run that fails before it has a session is retried twice. A run that is cut off (time limit, kill) still reports: its session is found from its transcript by start time and task.
- **Watching Heads:** while a Head runs (and for a minute after it ends) a band above the prompt shows one row per Head: a spinner (◌ queued, ✓ done, ✗ failed), its id, effort, a turn bar with `turns/maxTurns`, elapsed time and what it is doing now (`thinking`, `edit c.txt`, `search "TODO"`, `$ ls`) or how it ended. `/heads` opens a pane with every Head of the session: press its number to see its task, turn bar, edits, denials, cost and its last 8 tool calls (✓ done, ✗ denied). Both read Command Code's JSON event stream as it arrives and redraw once a second while a Head is live.
- **Status line:** Hydra writes its line to `~/.claude/hydra/status/<session id>.txt` while `/hydra` is on in that session (the file is emptied when it is off): `🐉 <head model> · <effort> | Heads 5h $spent/$limit | 7d $spent/$limit`, the Heads' Command Code spend against `headsFiveHourUsd` and `headsWeeklyUsd`. Your status line command prints it, which avoids the `⚠ <plugin>:` prefix Claude Code puts on a plugin's own status row. Add this (or see `examples/statusline.sh`) before the final `printf` of `~/.claude/statusline.sh`, where `$input` is the JSON Claude Code passes and `$out` your line:
  ```bash
  session_id=$(printf '%s' "$input" | grep -o '"session_id"[[:space:]]*:[[:space:]]*"[A-Za-z0-9-]*"' | head -1 | sed -E 's/.*"([A-Za-z0-9-]*)"$/\1/')
  hydra_file="$HOME/.claude/hydra/status/$session_id.txt"
  if [ -n "$session_id" ] && [ -s "$hydra_file" ]; then
    printf '%s\n\033[38;5;179m%s\033[0m' "$out" "$(head -1 "$hydra_file")"
  else
    printf '%s' "$out"
  fi
  ```
  Claude's own limits and running Heads are in `/hydra-usage` and `/heads`.
- **Effort:** Heads run with Command Code's `--effort`. In `auto` (the default, `headEffort`) the Lead picks per Head and never below `high`: `high` for a well-specified implementation, `xhigh` for multi-file work with some design judgement, non-trivial logic, edge-case tests or matching a mockup, `max` for a subtle bug, concurrency or state, an algorithm, a fragile cross-file change, or a retry after a Head got it wrong. DeepSeek V4.1 Flash has no `xhigh`, so it runs as `max` there. `/hydra effort=<level>` (`off`, `low`, `medium`, `high`, `xhigh` or `max`) fixes every Head at that level and overrides the Lead; `/hydra effort=auto` hands the choice back. A change reaches running Heads at their next round. A level the model lacks is raised to its nearest supported one (DeepSeek V4.1 Flash takes `off`, `low`, `high`, `max`), and each report shows the effort used.
- **Limits:** `maxMinutes` (default 40) per Head, at most 6 Heads at once (the rest queue in order).
- **Names:** every Head has a short name saying what it works on (`prefs-utils`, `login-tests`), used in the band, `/heads`, reports and `mcp__hydra__control`. The Lead passes `name`; without one Hydra makes one from the first source file the task names (`PreferenceUtils.kt` → `preference-utils`) or its first few meaningful words. Names are lowercase kebab, at most 20 characters, and unique per session (`-2`, `-3`).
- **Lead control:** `mcp__hydra__control` lets the Lead `list` Heads (one with no process behind it is flagged `NO LIVE PROCESS`), `stop` one by name or all, `clear` finished ones from the views, and turn Hydra `on`/`off` or set its `effort` and head model, so it never has to ask the person to stop a Head.
- **Watching without interrupting:** `/heads` and `/hydra-usage` are immediate commands, so they open mid-turn without touching Claude's work. An interrupted foreground call (Esc, a typed prompt) lets its Head keep running; the report then arrives as a message. Stop a Head on purpose with `s` in `/heads` or through `mcp__hydra__control`.
- **Stopping cleanly:** every Head, foreground or background, runs on the `session.start` worker. Cancelling a Head's tool call aborts it, and the stream read is raced against that stop, so a silent Head (a model thinking, a hung CLI) ends at once and is marked failed with the reason. A reload marks running and queued Heads as ended.
- **`/hydra <task>`:** the task is submitted as a prompt, so the Lead starts right after the command instead of on the next message.
- **Background:** `background: true` queues the Head for a worker that `session.start` owns and returns at once; the report arrives later as a message from the plugin. A plugin may not keep `$` in a variable, and a `tool.call` hook's `$` lapses a few minutes after the call returns, killing anything spawned under it; that is why the worker lives in `session.start`.

- **`.hydraignore` (lib/protect.ts):** `runHeadInside` calls `guardedPaths` with each root (`cwd`, `writeDirs`, `addDirs`) and its real path before any engine starts. A root with a `.hydraignore` runs `git -C <root> ls-files -z --cached --others --ignored --directory --exclude-per-directory=.hydraignore` (30 s); the result (`Guarded`: `paths`, the untracked `folders` among them, and the `ignoreFiles`) rides on `HeadNeeds.guarded` into each engine's settings builder, next to its `.env` handling: `guardedDeny` (Command Code, plus `SEARCH_DENY`), `buddyGuardedDeny` (and `buddyTools(shell, false)`: CodeBuddy's Grep checks `Read` rules only against the path it is given, so a directory search returned denied files' lines in a live probe), `codexFilesystem` (`none` per path, each `.hydraignore` `read` by exact path: Codex refuses any access but `none` on a glob), `agySettings` (guarded reads and writes; on a caseless disk every rule inside a root goes through `agySpellings`, and `agyCaseRefusal` refuses past `AGY_RULE_CAP` or a grant holding a credential folder), `opencodeConfig` (`deny(guarded)` through `anyCase`, `OPENCODE_IGNORE`) and `linkDenies` (`isGuarded`, compared in lower case). `formatReport` flags a changed `.hydraignore` (`isIgnoreFile`). No git, a git error, a timeout, truncated output or more than `IGNORE_CAP` (200) matches refuses the Head.
- **Checks (lib/check.ts):** a Head with `check` runs through `runChecked` (engines/index.ts), which wires `checkHead` to the engine (`run`, around the single-account or `runOnAccounts` path), `runCheck` (`/bin/sh -c` or `cmd /d /s /c` via `$.process.run`, `timeoutMs` from `checkMinutes`, at most 10 min, the call's own ceiling), the clock and the run record. `checkHead` is pure: tested with fake steps in hooks/check.test.ts. Fix rounds re-run the Head with `task + fixNote(...)`, `raisedEffort` (the Lead's pick one level up; a fixed `/hydra effort` still wins inside each engine) and the minutes left, like account switching. `outcomeOf` maps exit 0 to passed, 126/127 to unknown, the rest to failed; a rejected run (timeout, spawn failure) is unknown. `withCheck` puts `checkLines` at the end of Hydra's summary and the check's output after the Head's text. `hasCheckConsent` (store key `consent-check-v1`) asks in the Head tool's `tool.call` the first time a call carries `check`.

## Auto engines (internals)
`mode.engine` can be `auto`, with `mode.engines` the pool (stored in `ENGINES` order; empty means all four). `isAuto`, `poolOf`, `engineLabel` and `resolveHeadEngine` are the pure helpers; `engineOf` reads `auto` as the fallback engine, so code that needs one concrete engine for a Head must go through `resolveHeadEngine`.
- **Turning it on:** `readyEngines` runs `preflight` for each wanted engine (the ready ones form the pool, the rest are reported), `hasConsentAll` asks once for the engines with no saved answer (`AUTO_CONSENT_QUESTION`) and stores each engine's own consent key, so a later fixed `/hydra engine=codex` does not ask again.
- **Per Head:** `tool.call` for the Head tool runs `resolveHeadEngine(hydra, e.engine)`: a fixed session accepts `engine` only if it matches; auto requires one from the pool. The Head's model is `headModelFor(engine, undefined, hydra.headModel, defaultHead)` and an incompatible `model` input is dropped. Everything after that (`runHead`, rules, caps, reports) is the existing per-engine path.
- **Policy:** `autoPolicy` builds the Lead's text from `ROUTES` (one line per engine, only for the pool), `lockdownRules` and `envRule` per engine, and `autoEffortRule`. Edit `ROUTES` to change how Claude routes; keep each line to what the engine does, and label judgement as judgement.
- **Usage pane:** spend is read only when `commandcode` is in the pool; otherwise `AUTO_NO_SPEND`.
- **Smoke test (auto):** `/hydra engines=codex,agy`, then ask for two independent tasks (one hard, one bulk/mechanical) and check the plan names an engine for each, the Head calls carry `engine`, the band shows the engine column, and a call without `engine` is refused.

## The Antigravity engine (internals)
`engine` can also be `agy`. A Head runs `runAgyHead` → `runAgyRounds` → `runRoundAgy`, sharing `pump` with the other engines.
- **Command (`agyArgs`):** `agy -p <prompt> --model <base>-<low|medium|high> --sandbox --output-format stream-json [--conversation <id>]`. agy 1.4 takes the level only in the model id and refuses `--effort` beside it, so `agyModelId` builds it from `AGY_MODELS` (`gpt-oss-120b` has only `medium`; no effort is `low`). Each base names its usage pool (`claude` for Claude and GPT-OSS, `gemini`, `argon`), and with several accounts a limit cools `agy/<name>#<pool>` instead of the whole account. Never `--dangerously-skip-permissions`, and never `--add-dir` (it makes the project read-only in the sandbox). `runHead` keeps the Lead's `model` when it is in `AGY_MODELS`, else the session's, else `AGY_MODEL` (Flash). agy's own `search_web` and `read_url_content` tools run under these rules, so a Head can research the web though its shell has no network. Started by argument vector with `HOME=<head home>` in `env` and stdin closed (`pump` passes `input: ''`), so no shell is involved and the same line works on every platform.
- **Per-Head HOME (`writeAgyHome`):** `agy` reads permissions only from `~/.gemini/antigravity-cli/settings.json` (no flag, no env), so the Head's `HOME` is `~/.claude/hydra/heads/agy-<session id>-<head>/` with `.gemini/antigravity-cli/settings.json` (`agySettings`) and a copy of `antigravity-oauth-token` (a first-run wizard is not needed). `removeAgyHome` deletes it (only paths holding `/.claude/hydra/heads/agy-`); `sweepAgyHomes` deletes ones over a day old at session start. The Head's shell sees the fake `HOME`.
- **Rules (`agySettings`):** `action(target)` lists, deny over ask over allow; a directory target ends with `/`. Targets match one exact spelling, so on a disk that ignores case (`isCaseless`: `cwd` in swapped case exists) each deny inside a root is written in every letter case of the part below the root (`agySpellings`); another spelling of the root itself is outside the workspace and refused anyway. See the 0.11.0 changelog for the list. `.env` rules name existing files (`findEnvFiles`, `find … -maxdepth 8`, redone before each round by `writeAgySettings`), because targets are paths: a glob or regex target in `read_file` makes the sandbox refuse every command ("globs not supported"). `agyTempDeny` adds `write_file(/tmp/)` and the other temp folders unless a writable root lives in one (deny beats allow). Unmatched file access outside the workspace asks, which headless mode refuses.
- **Shell:** `command(*)` is allowed only with `shell: true`; the terminal sandbox (`--sandbox`) is what bounds it (no network, read-only outside the project and `writeDirs`; `/tmp` is writable unless denied). `AGY_SHELL_DENY` turns `DANGEROUS_SHELL` into `command(regex:(?:.*[;&|(]\s*)?<text>.*)`; plain prefix rules miss compound lines, `\b` is not supported, and an unanchored `.*<text>.*` blocks harmless text (`gh ` inside "through ").
- **Stream (`foldAgyRow`):** `init` (conversation id), `step_update` rows (`step_type` `tool` with `tool_name`, `tool_info.parameters` such as `CommandLine`, `TargetFile`, `AbsolutePath`; `ACTIVE` then `DONE`), then `result` (`status`, `response`, `usage`, `denied_actions[{action, display_name}]`). A denied file call still emits `DONE`, ends the run and only shows up in `denied_actions`, so a turn is one `DONE` tool call and edited files come from `bin/changed-files.py`.
- **Sign-in:** `agy` has no login subcommand: run `agy` in a terminal, choose Google OAuth, paste the code from the callback page, accept the terms (the data-sharing box is ticked by default). Preflight checks `~/.gemini/antigravity-cli/antigravity-oauth-token`.
- **Smoke test (Antigravity):** a throwaway git repo with `.env`, `sub/.env.local`, a `writeDirs` and an `addDirs` folder and a sibling under the home folder (not `/tmp`); build the settings, run the command with a prompt that tries one shell command at a time: an in-project append and create, a home sibling write, `.env`, `sub/.env.local`, a `writeDirs` write, an `addDirs` read and write, `rm -rf`, `git commit`, `curl`, and a harmless `echo`. Expected: only the project, `writeDirs`, `addDirs` read and the `echo` succeed.

## The Codex engine (internals)
`engine` can also be `codex`. A Codex Head runs `runCodexHead` → `runCodexRounds` → `runRoundCodex`, sharing `pump` with the other engines.
- **Command (`codexArgs`):** `codex exec [resume] --json -m <id> --skip-git-repo-check --ignore-user-config -c default_permissions="hydra" -c permissions.hydra.filesystem=<table> -c approval_policy="never" [-c model_reasoning_effort="<level>"] -- [<thread id>] <prompt>`. The shell wrapper closes stdin: `codex exec` otherwise waits on it ("Reading additional input from stdin..."). A Head runs in the person's `~/.codex` for auth only (`--ignore-user-config` drops their config). Never use `--dangerously-bypass-approvals-and-sandbox`, `-s workspace-write` (it makes `/tmp` and `$TMPDIR` writable) or `--full-auto`. Started by argument vector with stdin closed (otherwise `codex exec` waits for more prompt text).
- **Lockdown (`codexFilesystem`):** an inline TOML table, `"<path>"="read"|"write"|"none"`, each path once (where two entries meet the stricter access stands: none over write over read; Codex rejects a profile that names a path twice). `"/"="read"`; the home folder `"none"` unless a writable folder holds it, with each existing toolchain folder from `HOME_READ_DIRS` plus `headReadDirs` re-opened `"read"`; each `addDirs` folder `"read"` and `cwd` and each `writeDir` `"write"` (real paths, resolved with `realpath`, so a symlinked project matches the sandbox's view), dropping any inside a credential path; the repository's top level and shared `.git` folder `"read"` when `cwd` is a monorepo subfolder or a worktree (`gitReadDirs`); `<dir>/**/.env` and `<dir>/**/.env.*` `"none"` for every writable and readable folder; every credential path in `SECRET_PATHS` `"none"`; and `glob_scan_max_depth=6` (otherwise Codex prints a `**` warning per rule). More specific paths win, so a credential file inside an opened toolchain folder (`.config/git/credentials`) stays closed. `.git` is read-only inside a writable root without a rule. There is no network. A resumed thread takes the new profile, so tightening it between rounds works. An empty `HOME` refuses the Head.
- **Stream (`foldCodexRow`):** `thread.started` (the thread id: the session to resume), `item.started` / `item.completed` for `command_execution` (`command`, `aggregated_output`, `exit_code`), `file_change` (`changes[].path`), `agent_message` (the report), `reasoning`, `mcp_tool_call`, `web_search`, then `turn.completed` (`usage.input_tokens`, `output_tokens`) or `turn.failed`. A turn is one finished tool call. A non-zero command whose output reads "Permission denied", "Read-only file system" or "Operation not permitted" is a denial.
- **Edited files:** `file_change` paths plus `bin/changed-files.py` (mtime scan of `cwd` and `writeDirs`, git-aware), because a shell write has no event.
- **Side effects:** the sandbox leaves empty `.agents`, `.aws`, `.codex` folders in a writable root (removed after the Head if they were absent before) and Codex adds a `trust_level` entry per project to `~/.codex/config.toml`.
- **Models:** `gpt-6.1-sol` (default for Codex, `ENGINE_MODEL`), `gpt-6-luna` (fast, cheap), `gpt-6-astra`; all take low to max. `headModelFor` keeps the model when the engine can run it and otherwise falls back to the engine's default. Some ChatGPT plans refuse every model but `gpt-6-luna` ("not supported when using Codex with a ChatGPT account"): `runCodexRounds` then reruns the first round on `CODEX_PLAN_MODEL`, adds a ⚠ warning to the report and remembers the refused model for the session.
- **Smoke test (Codex):** a throwaway git repo with `.env`, `sub/.env.local`, a symlink to a sibling folder, an `addDirs` and a `writeDirs` folder; run the generated command with a prompt that tries, one shell command at a time: an in-project append and create, a sibling write, `/tmp`, `.env`, `sub/.env.local`, the symlink, `.git/hooks`, `git commit`, `curl`, `~/.ssh/id_rsa`, `~/.codex/auth.json`, a `writeDirs` write, an `addDirs` read and write. Expected: only the in-project work, `writeDirs` write and `addDirs` read succeed. The 0.10.0 changelog lists the live results.

## The CodeBuddy engine (internals)
`engine` is `commandcode` or `codebuddy`, set by the `headEngine` option or `/hydra engine=<name>` and kept in the session's `mode` state next to the Head model. Each Head records the engine it started on, so changing it never touches a running Head. A CodeBuddy Head runs `runBuddyHead` → `runBuddyRounds` → `runRoundBuddy`; the Command Code path (`runLockedHead`, `runRound`) is unchanged apart from sharing `pump`, the spawn-and-read loop.

`headEngine` defaults to `auto`, so a bare `/hydra` decides what to run on with `planOnboarding` (`lib/onboarding.ts`): `onboardingPlan(configured, ready)` is the pure decision (a ready configured engine as before, else one ready engine alone, several as an auto pool, none as `setupCard`). Consent is asked after the decision and before anything is stored, exactly as for a named engine. The first turn-on also appends `takeWelcome`, keyed `welcomed-v1` in `$.store`. The views' sums and bar maths are pure functions in `lib/format.ts` (`totalsOf`, `engineMixOf`, `timelineBar`, `bandLayout`), tested in `hooks/ui.test.ts`.
- **Command:** `codebuddy -p <task> --model <id> --output-format stream-json --verbose --permission-mode default --tools <list> --settings <file> --setting-sources local --max-turns N [--add-dir …] [--effort …] (--session-id <id> | --resume <id>)` (`buddyArgs`). No `--yolo`, no `bypassPermissions`, no `acceptEdits`: in `default` mode headless CodeBuddy refuses ("permission prompts are not available in non-interactive mode") anything its rules do not allow, so path-scoped `Edit`/`Write` allow rules are the lockdown. `acceptEdits` and an unscoped `--allowedTools Edit Write` let a Head write anywhere (verified).
- **Settings file (`buddySettings`):** written per Head to `~/.claude/hydra/heads/<session id>-<head>.json`, deleted when the Head ends (a session start sweeps files a crash left behind after a day). `allow`: `Edit`/`Write` under `cwd` and each `writeDir`, `Read` of each `addDirs` folder, `Bash` only for `shell: true`. `deny`: `.git` and `.env` / `.env.*` for `Edit`, `Write` and `Read` in every writable folder, every read-only folder for `Edit`/`Write`, and the dangerous shell list (`BUDDY_SHELL_DENY`, Command Code's list as `Bash(...)` globs). `PreToolUse` hook: `bin/head-guard.py` on `Write|Edit|MultiEdit|NotebookEdit`. `--setting-sources local` keeps the person's own user and project permission rules out of a Head.
- **Why the guard stays:** the `Edit(/abs/**)` rules match the path as written, so a symlink inside the project (`link-out/y.txt`) reaches a folder outside it. The guard resolves real paths and denies it; a denied write comes back as an error that says "outside the project".
- **Stream:** CodeBuddy's `stream-json` is Claude Code's format: `system/init`, `assistant` lines (one per content block, sharing a `message.id`), `user` lines carrying `tool_result`, then a `result` line (`subtype`, `result`, `session_id`, `usage`, `total_cost_usd`) and a trailing `system/init`. `foldBuddyRow` turns it into the events the live view already reads (a new `message.id` is a turn; `tool_use` queues and runs a call; a `tool_result` with `is_error` and a refusal wording is `tool_denied`), and collects edited files, refused calls and tokens, so there is no transcript to read. `permission_denials` in the result is empty even when calls were refused; do not use it.
- **Session and resume:** the first round passes `--session-id hydra-<head>-<time>`; later rounds `--resume <id>`. A Head that stops on a text-only reply is resumed like a Command Code one. Exit code is 0 even for an unfinished Head, so `HEAD DONE` and the `result` subtype decide.
- **Turn cap:** `--max-turns` is loose, so `runRoundBuddy` counts distinct assistant `message.id`s and stops the child when a round passes its cap (reported as `error_max_turns`, exit 8).
- **Cost:** `total_cost_usd` is always 0 (credits). Reports and the band show `tokensText(input, output)`; `/hydra-usage` says CodeBuddy has no dollar spend.
- **Effort:** `--effort` takes `minimal, low, medium, high, xhigh, max` and accepted every value tried, so there is no refusal to catch; Hydra's `off` is `minimal`.
- **Smoke test (CodeBuddy):** like the Command Code one: a throwaway repo with a sibling folder, an `addDirs` folder, a symlink to the sibling, `.env` and `sub/.env.local`; run a Head that tries an in-project edit and create, a sibling write, a new folder in `~`, the symlink, `.git/config`, a new `.git/hooks` file, an `addDirs` read and edit, `.env`, `sub/.env.local`, a new `.env.production`, a read of `/etc/hostname`; then once with `shell: true` and `ls`, `git status`, `rm -rf`, `rm -r`, `git commit`, `git push`, `curl`, `cat .env`, `sudo`, `npm install`. Expected: only the in-project work, `addDirs` read, `ls`, `git status` and a harmless `node -e` succeed. The 0.9.0 changelog lists the live results.

## The WorkBuddy engine (internals)
- **A CodeBuddy profile:** `workbuddy` runs the same code as `codebuddy` (`buddyArgs`, `buddySettings` with the write guard and `buddySecretDeny`, `foldBuddyRow`, `runBuddyHead` with `engine: 'workbuddy'`). Only the environment differs: `workbuddyEnv(home)` (lib/engines.ts) sets `CODEBUDDY_CONFIG_DIR=~/.claude/hydra/workbuddy-cli` (its own sign-in, settings and transcripts), `ACC_PRODUCT_CONFIG_PATH=~/.workbuddy-ai/cache/acc-product-config-v3.json` (the product definition the WorkBuddy app writes: endpoint, sign-in flow, model list; not a credential) and `CODEBUDDY_DISABLE_AUTO_MEMORY`, `CODEBUDDY_CODE_DISABLE_SESSION_SUMMARY`, `CODEBUDDY_PROMPT_SUGGESTION_DISABLED`, `CODEBUDDY_DISABLE_CRON`, `CODEBUDDY_DISABLE_IDE`, `CODEBUDDY_DISABLE_BROWSER_MCP` = 1. An extra account's `CODEBUDDY_CONFIG_DIR` goes over it. Default model `deepseek-v4.1-flash` (`ENGINE_MODEL`).
- **Undocumented:** `ACC_PRODUCT_CONFIG_PATH` is read by the CodeBuddy npm package but is not in Tencent's docs; a CodeBuddy update may drop it. The CLI bundled in the WorkBuddy app is headless-only and cannot sign in, so Hydra uses the npm build on `PATH`.
- **Preflight (`engineChecks`, lib/checks.ts):** `codebuddy --version` runs; the product file exists (else "Install the WorkBuddy app and sign in once…"); `~/.claude/hydra/workbuddy-cli/local_storage` has an entry (where CodeBuddy keeps its sign-in; existence only, never read). The sign-in command is `CODEBUDDY_CONFIG_DIR=~/.claude/hydra/workbuddy-cli ACC_PRODUCT_CONFIG_PATH=~/.workbuddy-ai/cache/acc-product-config-v3.json codebuddy`, then `/login`.
- **Spend:** credits, so tokens per Head (`WORKBUDDY_NO_SPEND`). Not on native Windows (`WINDOWS_ENGINES`).
- **Smoke test (WorkBuddy):** build `buddyArgs` + `buddySettings` + `workbuddyEnv` and run one round with `--max-turns 3` and the prompt "reply HEAD DONE". 15/10/26, CodeBuddy npm 2.164.0: `system/init` with `deepseek-v4.1-flash`, `result` `success` with `HEAD DONE`, exit 0. The lockdown is CodeBuddy's, whose smoke test above covers it.

## The OpenCode engine (internals)
OpenCode is **beta** in Hydra. Built and verified against OpenCode **v2.0.18**, whose CLI and config differ from the public v1 docs (`run --standalone`, no `--dir`, tool `shell` not `bash`, a `permissions` array next to the legacy `permission` object).
- **Command (`opencodeArgs`):** `opencode run --standalone --format json -m <provider/model> [-s <ses_…>] -- <prompt>`, cwd = the project, stdin closed by `pump`. `--standalone` runs a private server for the run instead of attaching to (or starting) the background `opencode serve --service`. Never `--auto`.
- **Environment (`opencodeEnv`):** `PWD=<cwd>` (`opencode run` changes to `$PWD ?? process.cwd()` first, and `$PWD` is inherited from Claude Code: without it a Head whose `cwd` is not the session's folder worked, and was matched, in the session's folder; found live), `OPENCODE_CONFIG=<file>` and the same JSON in `OPENCODE_CONFIG_CONTENT` (it outranks any config the person's environment names), `OPENCODE_CONFIG_PROJECT_DISABLE=1` and `OPENCODE_DISABLE_PROJECT_CONFIG=1` (v2 reads the first and falls back to the second; a project `opencode.json` or `.opencode/` cannot add rules, plugins or MCP servers), `OPENCODE_DISABLE_AUTOUPDATE=1`, and `XDG_CONFIG_HOME` = `OPENCODE_CONFIG_DIR` = an empty per-Head folder, so `~/.config/opencode` (provider API keys) is not loaded and is not the config folder OpenCode's default rules let an agent read. `XDG_DATA_HOME` is left alone (sign-ins and the free models' entitlement live in its database) unless an account sets it.
- **Files:** `~/.claude/hydra/heads/opencode-<session>-<head>.json` (0600) and the folder `opencode-<session>-<head>/` (0700), removed when the Head ends; `sweepOpenCodeFiles` removes ones over a day old at session start. OpenCode wrote nothing into the config folder during the smoke tests.
- **How OpenCode matches (v2.0.18, read from the binary):** a pattern becomes `^…$` with `*` → `.*` and `?` → `.` under the `s` flag, so both cross `/`; brackets and other regex characters are escaped; matching is case-sensitive; the last matching rule wins. `FileAccess.resolve` is a lexical `path.resolve` (no realpath, no case folding). A path under `cwd`, or under the project root (`Project.resolve`: the first folder up from `cwd` holding `.git`, as `git rev-parse --show-toplevel` names it, or `.hg`; `cwd` itself when there is none or git fails), is matched **relative to `cwd`** (`sub/.env`, `../x`) and never reaches `external_directory`; any other path is matched absolute and does. `opencodeMatches`/`ruleFor` mirror this for the tests.
- **Project root (`projectRootRefusal`, `vcsRootOf`):** because of the above, a Head whose `cwd` is a monorepo subfolder could read and write the whole repository through `../`, absolute denies (read-only `addDirs`, `SECRET_PATHS`) would not match those relative paths, and a home folder that is a git repo would expose `../../.ssh`. Hydra walks up from the real `cwd` as OpenCode does and refuses the Head unless the root found is `cwd` itself (or there is none, or git does not know the `.git`); a check that cannot run refuses too.
- **Lockdown (`opencodeConfig`):** the legacy `permission` object, which OpenCode turns into ordered rules. `"*": "deny"` comes first; then `read` `{"*": allow, denied links, OPENCODE_ENV: deny}`, `edit` `{"*": allow, read-only addDirs, writeDirs inside them re-allowed, denied links, OPENCODE_GIT, OPENCODE_ENV, OPENCODE_PROTECTED: deny}`, `glob` allow, `todowrite` allow, `external_directory` `{"*": deny, "<writeDir or addDir>/*": allow}`, and `bash`, `shell`, `grep`, `execute`, `webfetch`, `websearch`, `task`, `subagent`, `question`, `skill`, `lsp`, `doom_loop`, `list_mcp_resources`, `read_mcp_resource` deny (also as `tools: {…: false}`, which OpenCode turns into the same rules). `SECRET_PATHS` under home are denied for `read`, `glob` and `edit` as `<home>/<p>` and `<home>/<p>/*`, and `opencodeGrantRefusal` refuses an `addDirs`/`writeDirs` folder that holds one (a grant of the home folder would let `~/.SSH/…` through on a case-insensitive disk). Case: macOS disks ignore case and the rules do not, so `.GIT/hooks/pre-commit` and `.ENV` got past the old rules. `OPENCODE_GIT` is every case variant of `.git` (8) as `v`, `v/*`, `*/v`, `*/v/*`; `OPENCODE_ENV` every variant of `.env` as `*v` and `*v.*` (`*` also matches the empty text, so these cover `.ENV`, `sub/.Env` and absolute paths); `OPENCODE_PROTECTED` (`.opencode/`, `opencode.json*`, `.claude/`, `.codebuddy/` at any depth, lower case only) is denied for edits. Path-specific denies (links, read-only folders) are written by `anyCase`: the first two letters in both cases and every later letter as `?`, so any spelling matches at the cost of a few same-shaped paths; under a granted folder outside `cwd` that folder's own spelling stays exact, because `external_directory` refuses any other. `rulesOf` keeps the order: a pattern that reads as an array index (`2024`) would be put first by JSON, ahead of `*`, so it gets a trailing `*`. The config is compact JSON and is refused above `OPENCODE_CONFIG_LIMIT` (120,000 characters, under Linux's 128 KiB per environment variable). Nothing is ever `ask`: headless `run` rejects an ask and aborts the whole run (`Session interrupted: shutdown`). A denied tool is removed from the model's tool list, so the model reports "not available" instead of trying it; denying `execute` also removes Code Mode and every tool behind it (`tools.browser.*`, `tools.opencode.*`, MCP).
- **Why no shell:** `shell` is not path-checked (research: `cat ../outside/o.txt` succeeded with `external_directory` denied), so `shell: true` is ignored for OpenCode and the policy says so. **Why no grep:** OpenCode's grep returns matching lines from `.env` files that `read` refuses.
- **Symlinks (`bin/symlinks.py`, `linkDenies`):** OpenCode checks the path as written, so `link-out/y.txt` (a project symlink to a sibling folder) was written outside the project under the first config. `symlinks.py` walks `cwd`, every `writeDirs` and every `addDirs` folder (`scanRoots`: one that lies in another is not walked twice) with nothing skipped or followed and prints every link with its real target; a folder it cannot list, a timeout (60 s), a cut-short output or anything unexpected refuses the Head (`linkScanResult`). `linkDenies` then denies a link for `read` when its target is outside every readable folder or is a `.env` file, and for `edit` when its target is outside every writable folder, in a read-only one, or in `.git` or a protected folder. A link to a folder above itself (`a -> .`) or to a folder that holds a denied link or read-only folder is denied too, repeated until nothing changes, so `a/link-out/x` cannot get around the deny on `link-out`. Inward links are filtered before any count, so a pnpm tree cannot crowd out an outward link; more than `OPENCODE_LINK_CAP` (100) links to deny refuses the Head. A link created during the run is not covered (an OpenCode Head has no tool that makes one).
- **No write guard:** OpenCode has no PreToolUse hook, so nothing checks real paths beyond the above. The report lists every edited file (`write`/`edit`/`apply_patch` targets plus `changedFiles`), flags any write outside the project, and `changeWarnings` adds a ⚠ line for a changed file whose real path is inside a `.git` folder (any case) or outside the project and `writeDirs`.
- **Not covered:** hard links (a pnpm store links files into `node_modules` by inode, so editing one edits the store copy); `.claude/`, `.opencode/` and `opencode.json` in other letter cases; other files that run code later (`.envrc`, `package.json` scripts, `.vscode/tasks.json`, other engines' project config); other project secrets (`local.properties`, keystores).
- **Stream (`foldOpenCodeRow`):** one JSON object per line, each with `type`, `timestamp`, `sessionID` (the `ses_…` id to resume). `step_start` is a turn; the `text` parts of the last step are the report; `tool_use` arrives once with its final state (`completed` or `error`; input key `path`, `shell` has `command`, `apply_patch` has `patchText`), so it is queued, run and finished at once; an error starting `Permission denied` is a refusal; `step_finish` carries `tokens` (input, output, reasoning, cache) and `cost`, but only for steps that end in tool calls, so the last text-only step is not counted and token totals undercount; `error` rows (`provider.auth`, `provider.rate-limit`, `provider.quota`, `provider.no-route`, `aborted`…) become the round's `errors` as `type: message`, which `isQuotaFailure` reads for account rotation. A completed call to any tool outside read/write/edit/apply_patch/glob/todowrite is a ⚠ line in the report.
- **Watchdog:** research saw about 40% of runs print nothing until killed. `pump` takes `idle` limits (`OPENCODE_WATCHDOG`: 90 s to the first stdout, 5 min between outputs; `silenceLeft` is the pure part) and stops a silent child with signal `idle`; the round is retried once (`idleRetryRound`: once OpenCode has named a session, the retry resumes it with the continue prompt, so no second session starts while Hydra keeps the first id), and a second silence ends the Head with "OpenCode produced no output … twice". No hang happened in the five live runs here.
- **Rounds, turns, effort:** the HEAD DONE resume loop, `MAX_ROUNDS`, `START_RETRIES` and a Hydra-counted turn cap (`step_start`s), as on the other engines. OpenCode takes no effort level, so `effort` is ignored.
- **Models:** `ENGINE_MODEL.opencode` is `opencode/deepseek-v4.1-flash-free` (free, no account; listed by `opencode models`). `isModelFor('opencode', …)` accepts any `provider/model` except Command Code's `deepseek/…`, and the other engines refuse `opencode/…`. Providers defined only in `~/.config/opencode/opencode.json` are not available (the per-Head config home hides that file); providers signed in with `opencode auth login` or an API key in the environment are.
- **Preflight (`engineChecks`):** `opencode --version` (a warning below v2) and `opencode auth list --standalone --format json` (a warning when it lists no provider: only the free models then; plain `auth list` prints "No authenticated integrations", which the old check took for a sign-in). Both run through `opencodeCheckInit`: from the home folder (else the plugin root) with `PWD` set to it and both project-config variables at 1, so no project's `opencode.json` or `.opencode/` plugin loads. Plain `opencode auth list`, `models` and `debug` attach to the background service and start it when it is not running.
- **Accounts:** an extra account sets `XDG_DATA_HOME=<dir>/data` (sign in with `XDG_DATA_HOME="<dir>/data" opencode auth login`); its sign-in check runs `auth list --format json` on that data folder and wants a `credential` connection (`opencodeProviders`; API keys in the environment show as `env` and do not count). `opencode.db` proves nothing: any OpenCode command creates it, `auth list` included, and v2 keeps credentials in that database (`auth.json` is only imported from v1). A fresh data folder loses the free models (403 `provider.auth` "free tier can only be used from within OpenCode"), so an extra account needs a real provider.

## Accounts (internals)
`lib/accounts.ts` holds everything. An `Account` is `{ engine, name, dir? }`; `default` has no `dir` and no override. Extra names live in `$.store` `accounts-v1` (`Record<engine, string[]>`), their folders at `~/.claude/hydra/accounts/<engine>/<name>/` (a `.keep` file makes it), cooldowns in `cooldowns-v1` (`"<engine>/<name>"` → end in ms) and last use in `lastUsed-v1`. `ACCOUNT_SUPPORT` is a `Partial<Record<Engine, …>>`: codex sets `CODEX_HOME`, codebuddy `CODEBUDDY_CONFIG_DIR`, and agy has no env (its Head already runs with its own `HOME`, so only the token source changes: `writeAgyHome` copies `<dir>/.gemini/antigravity-cli/antigravity-oauth-token`). An engine left out has one account and none of the rest runs for it.
- **Rotation:** `runHeadInside` (engines/index.ts) asks `accountsOf`; with one account it calls `startHead` as before. With several, `runOnAccounts` wires `rotateAccounts` (pure, tested with fake steps) to the store and the run record: `pickUsable` (cooldowns, the `accountStrategy` through `pickAccount`, and a lazy sign-in check cached for the session, skipping an extra account that is signed out) → `startHead` (the engine's `run<Name>Head` with `env` or `tokenDir`; `pump` already sets `env` over the host's) → on `!isDone` with `isQuotaFailure(result.failure)`: `recordCooldown` (`cooldownFrom`) and the next account, up to one run per account, the task plus `switchNote(files)`, the Head's remaining minutes. The result's text starts with `accountsLine`; `HeadRun.account` is set for the views.
- **Failure text:** the engines return `{ text, isDone, failure, files }`. `failure` is the round's `errors` (the CLI's stderr plus its own failure rows: Codex's `error` events, a CodeBuddy `result` with an error subtype, read by `buddyFailureText` from its `result`, `errors` and `errors_info` (a usage limit comes only in the last two, with exit 0, and a CodeBuddy round that stopped on one is not resumed), an Antigravity result that is not `SUCCESS`), set only when the Head is not done. `isQuotaFailure` is never run on the model's report, because code that handles rate limits would match.
- **Validator:** `$` is followed only into function declarations, so the per-engine sign-in checks are named functions called from `checkSignIn`, not table entries. `codex login status` with the account's `CODEX_HOME` is exit 0 when signed in; Antigravity is a token file's existence; CodeBuddy and WorkBuddy only that the folder holds more than `.keep` (the default account is not checked); OpenCode that `opencode auth list --format json` on the account's data folder names a stored `credential`.
- **Not verified live:** a second real account on each CLI. The env variables (`CODEX_HOME`, `CODEBUDDY_CONFIG_DIR`) and the Antigravity `HOME` come from each CLI's documented behaviour; sign one extra account in per engine and run a Head on it before releasing, and with `accountStrategy` `spread` check that two Heads use two accounts.

## Pitfalls already learned
- 2026-10-08: Command Code checks both a path as written and its real location against deny rules, so a write through a symlink in the project to a sibling folder was already denied by that sibling's rule. Opening one needs `writeDirs`, which removes the rule as well as widening the guard.
- 2026-10-08: path deny rules have `*` (one name, dotfiles included), `?` and `**`, but no negation and no character classes, so no rule can deny "a new folder in `~` other than the project", and `write_file` creates missing parents. A `PreToolUse` hook in `settings.local.json` fires under `--yolo` before the tool runs and its deny is final, so the write guard closes that gap. A hook that crashes or times out lets the tool run.
- 2026-10-12: CodeBuddy's `acceptEdits` mode and an unscoped `--allowedTools Edit Write` let a Head write to a sibling folder, a new folder in `~`, `.git/config` and read `.env`; only `default` mode with path-scoped allow rules refuses them. `Bash(rm -r:*)` does not match `rm -rf`; glob rules (`Bash(rm -r*)`) do. A path rule does not follow a symlink out of the project, so the write guard stays.
- 2026-10-12: CodeBuddy's `--max-turns 2` let a Head run 13 turns and finish; Hydra caps turns itself. Its `result.permission_denials` stays empty when calls are refused, and `total_cost_usd` is 0.
- 2026-10-08: on Windows, Command Code 1.65 matches a rule `//X` as `/X` and any other rule against the project, so no `Edit(...)` rule can deny a `D:/…` path and a `--yolo` Head writes anywhere (a live Head wrote outside the repo despite `Edit(//D:/…)` and `Edit(D:/…)` rules). Hydra refuses Windows project paths (`windowsPathRefusal`) instead of running unlocked; use WSL.
- 2026-10-07: Command Code's `-p` mode blocks edits, writes and shell commands unless the run uses `--yolo`, in every permission mode; `accept-edits`, `auto-accept` (an alias) and `dont-ask` with allow rules all fail. Deny rules are the only control left under yolo, hence Hydra's generated deny list.
- 2026-10-07: one denied call cancels every other call in the same batch ("Skipped — another tool call in this batch was denied"), and a model that keeps hitting denials often ends the run. Grant reads up front with `addDirs`.
- 2026-10-07: Command Code ends a `-p` run on any text-only reply, and some models reply with text before acting ("I'll start by reading…"). That is why every task ends with the `HEAD DONE` rule and unfinished runs are resumed.
- 2026-10-07: exit codes are 0 done, 8 turn cap, 9 empty model reply; all three are resumable.
- 2026-10-07: Command Code writes a session's `.jsonl` transcript lazily; at first only `.meta.json` and `.checkpoints.jsonl` exist, so a missing transcript does not mean a dead Head. The first line of `.checkpoints.jsonl` holds the prompt and `createdAt`.
- 2026-10-07: a refusal reads "Blocked by permission deny rule …" (yolo) or "requires permissions" (print-mode gate); the transcript reader must treat both as denials, or refused writes look like edits.
- 2026-10-07: a background Head spawned from a `tool.call` hook died about 3 minutes later; run long-lived work from `session.start`'s worker. A plugin may not store `$` in a variable (validate rejects it).
- 2026-10-08: a hook's own time is capped at 10 s per dispatch, and awaiting a plain promise counts; a `$` call in flight does not. A hook that must wait longer (the foreground Head) waits through `$` calls such as `$.process.run(['/bin/sleep', '1'])`.
- 2026-10-08: a foreground Head run under a `tool.call` hook's `$` stayed "running" forever after its call was cancelled: the child died with the call, and the hook could no longer record it. Every Head now runs on the worker's `$`. Set `statusLine.refreshInterval` (e.g. 2) so the status line shows `/hydra` on/off without waiting for the next message.
- 2026-10-07: big view files (1,500+ lines) took DeepSeek Heads past 40 minutes; split such work or raise `maxMinutes`, and expect a follow-up Head to finish it.
- 2026-10-08: Command Code's grep tool ignores `Read` deny rules, and path-scoped `Grep(...)` or `Search(...)` rules never fire; only a bare `Grep` deny stops it. Pointing grep straight at `.env` is caught by `Read(.env)`, but a search over `.` or a folder is not.
- 2026-10-08: `Read(.env.*)` and `Edit(.env.*)` match nested files such as `sub/.env.local`. Shell rules match the command text, not the files it touches, so `Shell(*.env*)` blocked `grep "process.env"` yet let `grep -r SECRET .` read every `.env`.
- 2026-10-08: Claude Code's auto mode refuses to let Claude launch a `--yolo` Head from Bash for a probe, even with the person's go-ahead. Write the probe as a script and have the person run it with `! bash <script>`. macOS has no `timeout`; use `perl -e 'alarm shift; exec @ARGV' 600 …`.
- 2026-10-08: Command Code refuses an effort level the model lacks before it starts (exit 1, `Unknown effort "medium". Supported: off, low, high, max.`), and a resumed session restores the last effort it recorded unless `--effort` is passed again. Hydra passes `--effort` on every round.
- A plugin's `command.run` hook must not call `$.command.run` (the engine refuses it and nothing answers the command), so `/hydra` only tells the person to run `/model`.
- Parallel Heads share one checkout. Give them disjoint files, read each report's own edited-file list rather than `git status`, and tell a Head never to delete a type another file still uses.
- Heads cannot build an Xcode project safely in a shared checkout (a fresh build folder clones every package); the Lead builds and tests.


## Layout
- `.claude-plugin/` — the mod manifest and the marketplace file
- `hooks/` — the hooks that drive it, and their tests
- `bin/cc-usage.py` — reads Command Code transcripts: spend windows, a Head's report, a lost session
- `bin/head-guard.py` — the write guard Command Code and CodeBuddy run before each Head write or edit
- `bin/changed-files.py` — lists the files a Codex or Antigravity Head changed, by modification time
- `types/` — the state contract
- `examples/statusline.sh` — a full status line command that prints Hydra's line
- `CHANGELOG.md` — what changed in each version

The SDK type definitions in `.claude-plugin/types/` are generated by the engine when it loads the mod and are not committed.
